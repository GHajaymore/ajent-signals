## 1. Cloudflare account (Worker + Pages + KV)

Everything currently lives under the personal Cloudflare account (`golferajay`).

- **Worker**: `ajent-signals-worker` → served at
  `https://ajent-signals-worker.golferajay.workers.dev`
  (`worker/wrangler.toml` line 1: `name = "ajent-signals-worker"`).
- **KV namespace**: `worker/wrangler.toml` lines 14-16 —
  `binding = "AJENT_KV"`, `id = "422c04e36c574a6f831151c871bce2c0"`.
  On the new account, **create a fresh KV namespace and paste its new id here.**
- **Pages project**: `ajent-signals` (deploy target of `wrangler pages deploy`).

**KV state resets on the new namespace.** The live data is two blobs:
`SIGNALS|ALL` (current signals) and `RECORD|ALL` (paper record: open positions +
closed trades + lastClose). They're rebuilt automatically by the cron within a few
ticks, so a fresh namespace is fine — the only loss is the current open paper
positions and any closed history (currently ~0 closed trades). No migration needed
unless you specifically want to preserve the record (KV bulk export/import).

**Worker secrets are per-account — re-set on the new account after `wrangler deploy`:**
- `ADMIN_KEY` — guards `GET /admin/tick` (force a cron run post-deploy). Added this
  session; a NEW random value is fine. If unset, `/admin/tick` just 404s (fails safe).
- `PRO_SECRET` — signs Pro tokens; **unset = the Pro gate is open** (current state,
  so `/signals` `/trades` are public). Only set when commercialising.
- `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, and the `STRIPE_PRICE_*` vars
  (`wrangler.toml` lines 23-24, currently `price_REPLACE_*` placeholders) — only for
  real payments.
- `DATA_API_KEY` — only if `DATA_PROVIDER` is switched from `yahoo` to `twelvedata`.
